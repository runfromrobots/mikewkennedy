# Project: Michael Kennedy (MK) Portfolio Site

Personal portfolio/resume site for Michael Kennedy, a UX Research Leader (13+ years) targeting Senior/Lead-level UX Research roles, fully remote. The site's self-description headline is "UX Research Leader" (chosen over "Senior UX Researcher"), with the About copy naming past titles: Principal UX Researcher, UX Designer / Researcher, and UX Research Operations specialist. Static site, no build step, no framework.

## Stack

Plain HTML/CSS/JS. No React, no bundler, no dependencies. Fonts loaded via Google Fonts CDN link tags in each HTML file's `<head>`.

## File structure

```
index.html                     homepage (hero, about, experience, toolkit, work, testimonials, contact)
styles.css                      shared stylesheet for the whole site
script.js                        shared JS (footer year, nav scroll-spy, carousels, site banner)
case-studies/index.html         case studies landing page (links back via ../)

images/                         drop images here, reference as images/filename.jpg
.nojekyll                        present so GitHub Pages serves files as-is

```

## Design system

* Colors: navy `#0A2540` (surface accent — buttons, contact section), electric cyan `#22E5FF`/`#33CFEA` (single accent — headings, links, borders, buttons), near-black `#08090D` (background), see `:root` in styles.css for full token list. The `--teal`/`--teal-deep` variable names are historical (kept so far fewer call sites needed touching) but now hold cyan values, not teal. The site was simplified to one accent color: the magenta secondary accent (`--accent-magenta`) and the purple hover accent (`--accent-purple`) were both retired and their tokens removed entirely — don't reintroduce a second accent color without being asked.
* Type: Newsreader (display/headlines, a classical high-contrast serif — replaced Fraunces in a typeface-pairing pass, chosen over a bolder "Space Grotesk + JetBrains Mono" tech-leaning option and a same-fonts-just-resized option), Public Sans (body, replaced Inter), Space Mono (labels, dates, eyebrows, tags, nav — all mono/label text site-wide via `--font-mono`, replaced IBM Plex Mono). Space Mono only ships weights 400/700 (no 500), so anything that needs to look bolder than body text uses 700, not a synthetic in-between weight. VT323 (a pixelated CRT-terminal font, an earlier label-text choice predating even IBM Plex Mono) was tried and removed for being hard to read at small sizes — don't reintroduce it.
* Hero graphic: the original animated "signal convergence" SVG (research sources converging into one insight node) was replaced with a two-photo collage, later swapped from a professional IBM Research photo to a warmer personal one. Current photos: `images/dogs-office.jpg` (larger, Michael with his two dogs at his home office desk) and `images/taiwan-team.jpg` (smaller, overlapping the first photo's corner, working with colleagues in Taiwan). Both are masked into organic shapes via CSS `border-radius` percentages rather than plain rectangles — `.hero-photo-blob` on the main photo, `.hero-photo-blob-accent` on the accent photo, a second/smaller blob with a distinct silhouette from the same shape family (not identical, not a clashing shape language) — chosen after a design critique flagged an earlier version's mismatched blob + spiky-star clip-paths as an inconsistency; both still share one plain 2px cyan border rule. There are no animated effects on the hero photos (or anywhere on the site — see Effects below); an earlier CRT scan-sweep and a fade/slide-in entrance animation were both tried and removed. `images/ibm-research.jpg` (the previous main hero photo) and `images/hero-photo.jpg` (the alley/sunglasses photo, unused even earlier) are both no longer referenced anywhere — kept in `images/` in case either gets placed elsewhere later.
* Keep all new sections consistent with this system rather than introducing new colors/fonts
* Spacing, small-text sizing, and breakpoints are systematized on the Carbon Design System (github.com/carbon-design-system) scale — CSS custom properties prefixed `--cds-` in `:root` (spacing-01 through 13, a handful of type-scale steps, a motion duration/easing pair). This is a token-level adoption only ("Option A"): the site's own display/body typefaces and the signature SVG structure are unchanged — deliberately not a full swap to literal Carbon components/theme, which would clash with the site's personal-portfolio identity. (The brand *colors* were later overhauled separately for the hacker theme below — Option A was about spacing/grid/type-scale infrastructure, not colors.) Breakpoints follow Carbon's md (672px) and lg (1056px). When adding new spacing/gaps, reach for a `--cds-spacing-*` token instead of a new hardcoded px value.
* The type scale (`--cds-caption-01`, `--cds-body-compact-01`/`--cds-body-01`/`--cds-body-02`, `--cds-heading-03`, plus the `h1`/`h2` `clamp()` sizes) was deliberately re-stepped in a later pass: `--cds-caption-01` (nav, eyebrow, tags, dates, footer, all mono/label text) had earlier been bumped from Carbon's literal 0.75rem up to 1.125rem for legibility, back when VT323 needed the extra size to stay readable at small sizes — but that inflation was never scaled back down after VT323 was replaced with a properly legible mono face, so labels had drifted to nearly the same size as body text (1.1875rem) and even `h3` (1.25rem), flattening the hierarchy. Caption is now `0.875rem`, body tokens are unified at `1.125rem` (no legibility regression, just no longer redundant with a bumped caption size), `--cds-heading-03` (`h3`) is `1.375rem`, and `h1`/`h2` got slightly wider `clamp()` ranges — each level is now a clear, consistent step down from the one above. `.log-company` (Experience section) is hardcoded rather than token-based, at `1rem`, so it still reads larger than `.log-date` (which reads off `--cds-caption-01`) for visual prominence. Since every one of those elements reads off these tokens, don't hardcode a smaller font-size on top of them for new label-style text, and don't let the caption/body/heading sizes drift back toward each other.
* Buttons, simplified: `.btn-primary` is flat solid `--teal-deep` with dark (`--paper`) text; `.btn-secondary` is transparent with a `--teal` border and `--teal-deep` text — the site's one outline/bordered-transparent style, used deliberately for visual variety against the solid primary. Hover: `.btn-primary:hover` darkens slightly to `--teal`; `.btn-secondary:hover` fills solid `--teal-deep` with dark text. No gradients, no glow, no separate purple hover accent — that "unified purple hover" treatment and the magenta/cyan gradients were both removed as part of a deliberate simplification pass (see the top-of-file note in styles.css). Every button still uses the `.btn-large` (or `.btn-header`) treatment per Fitt's Law, but `--action-btn-size` was shrunk from 80px to 52px (3.25rem) — still comfortably large, no longer oversized. The header is a normal flex row now: `.site-header` is just sticky/bg/border, and `.header-inner` (inside `.wrap`) is the single flex container holding brand, nav, and the header button together — the old "button bleeds outside `.wrap` to reach the page edge" treatment and its `.header-content`/`.brand-spacer` wrapper divs were removed along with it. Paired buttons (`.hero-actions`, `.contact-links`) now use `gap: var(--cds-spacing-03)` (a small visible gap) instead of touching at `gap: 0` — the flat/bordered button style no longer needs a seamless shared-gradient illusion between the two. All button color rules live in one place (base Buttons section) — don't re-scatter overrides across a separate "effects layer."
* Below the 672px breakpoint, `.site-nav` collapses behind a `.nav-toggle` hamburger button (three plain `<span>` bars) added to `.header-inner` on every page, right after `</nav>` and before the header CTA button. Clicking it toggles `.is-open` on `.site-nav`, which then renders as a full-width dropdown panel positioned `absolute` below the header (`.site-header`'s `position: sticky` is what gives that panel its containing block). The toggle logic lives in script.js: clicking a nav link closes the panel, and so does Escape. This replaced an earlier version of the site that simply hid the nav below 672px with no mobile replacement at all — don't reintroduce that gap.
* **This site has one theme only: a permanent dark "hacker-adjacent" theme**, deliberately calmed down from an earlier, louder terminal/CRT treatment (see Effects below). There is no light mode, no toggle, and no `prefers-color-scheme` switch — that was tried and deliberately removed. Don't reintroduce a light theme or make the palette conditional without being asked.
* Effects layer, near the end of styles.css (labeled "Effects"): no animated effects at all, anywhere on the site. Heading glow (`text-shadow` on h1/h2/h3), blurred gradient blobs behind the hero and `.contact`, a page-wide scanline texture (`body::after`), an RGB-split glitch flicker on hover (`@keyframes glitch-flicker`), a CRT-style scan sweep across the hero photos, and a photo fade/slide-in entrance animation were all tried at various points and removed — the site settled on a fully static, calmer surface: flat color, clean type, one accent, nothing moving. Don't reintroduce any of those without being asked. Functional UI transitions (button/nav-link hover color changes, the site-banner's expand-on-hover) are a different category and are fine; if adding a genuinely new decorative effect, confirm `prefers-reduced-motion` still disables it (the reduced-motion rule at the top of styles.css covers this automatically).
* Experience section (`#log` / `.experience`) is `--paper-raised` (a shade lighter than the page's `--paper` background) so it lifts slightly off the page. The zebra-striping on alternating `.log-entry` rows (a faint cyan tint via `nth-child(even)`) was removed as part of the simplification pass — don't reintroduce it without being asked.
* Each `.log-when` block splits company name and date into separate `.log-company` / `.log-date` spans (not a single `<br>`-joined string). Both use Space Mono. `.log-company` is upsized (1rem), bold weight (Space Mono has no medium weight, so this uses its 700 rather than a synthetic in-between), uppercase, letter-spaced, cyan, for visual prominence; `.log-date` stays small (`--cds-caption-01`), regular weight, `--ink-soft` colored, understated. The original split-vs-single-string treatment was chosen from three side-by-side options (an all-Fraunces editorial option and an Inter/Plex hybrid were the other two, back when the site used Fraunces/Inter/IBM Plex Mono) — don't relitigate the split without being asked.
* The "MK" brand logo in the header is a normal small inline circle (40px, with a 1px `--line`-colored border) sitting in the header's flex flow alongside nav and the header button. It used to be deliberately oversized (120px) and bleed down past the header's bottom edge via `position: absolute` (with an invisible `.brand-spacer` holding its footprint) — that bleed treatment was removed as part of the simplification pass. Don't reintroduce the oversized/bleeding version without being asked.
* `--heading` is a separate token from `--navy` (cyan vs. navy) so headings/text use the accent color while navy surfaces (buttons, the contact section, the skip link) stay literally navy — when adding new navy-colored text (not a background/fill), use `var(--heading)`, not `var(--navy)` directly.
* `body { color-scheme: dark; }` is set so browser chrome (scrollbars, form controls) matches.

## Conventions

* No em dashes in any content or copy written for this project
* Avoid "it's not X, it's Y" contrasting constructions in copy
* Keep prose concise and direct, avoid over-explaining
* Relative links only (`case-studies/`, `../`, `images/...`) so the site works correctly whether served from a domain root or a GitHub Pages subpath
